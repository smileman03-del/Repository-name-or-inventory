# 제품 소개 영상 만들기

`scripts/make_video.py` 한 파일이 **음악 합성 → 캐릭터/장면 그리기 → 프레임 렌더링 → ffmpeg 인코딩**을 모두 처리한다. 1280×720, 30fps, 45초, 영상+오디오 MP4가 나온다.

## 기본 구성 (45초)

| 장면 | 시간(사진 없음) | 시간(사진 있음) | 내용 |
|---|---|---|---|
| 인트로 | 0~9 | 0~7 | 제목 페이드인(0.4초부터) + 부제 |
| 사진 스토리 | — | 7~16 | 실제 사진 배경 + 문구 패널 + 캐릭터 스티커 (사진을 줄 때만) |
| 특징 1 | 9~19 | 16~24 | 파스텔 배경, 눌리는 캐릭터, 하트 |
| 특징 2 | 19~29 | 24~32 | 하늘·언덕, 통통 뛰기 |
| 특징 3 | 29~38 | 32~39 | 밤하늘, 잠든 캐릭터, Z |
| 마무리 | 38~45 | 39~45 | 제목 + 행동 유도 문구, 마지막 1.6초 페이드아웃 |

장면 사이는 0.8초 크로스페이드. 배경 음악은 4코드(Cmaj7·Am7·Fmaj7·G6) 반복 패드 + 오르골 멜로디 + 잔향이며, 잠자리 장면에서 자동으로 작아지고 끝에서 페이드아웃된다.

## 작업 순서

1. **받아야 할 정보를 먼저 확인한다.** 제품이 무엇인지, 제목, 장면별 핵심 문구, 쓸 사진/로고, 길이. 없으면 짧게 물어본다.
2. **문구에 검증 안 된 주장을 넣지 않는다.** "100% 안심", "안전 인증", "국내 최초" 같은 표현은 사용자가 근거를 줄 때만 쓴다. 기본은 촉감·귀여움 같은 느낌 중심 문구.
3. **스크립트를 복사해서 수정한다.** `scripts/make_video.py`를 작업 폴더나 scratchpad로 복사한 뒤 바꾼다(원본은 템플릿으로 보존).
   - 문구: 각 `sceneN` 함수 안의 `put_text(...)` 호출
   - 색·배경: 파일 위쪽 `BG = {...}` 와 장면별 `c`, `c2` 색
   - 캐릭터: `make_char()` (제품이 티라노가 아니면 여기를 다시 그리거나, 사진으로 대체)
   - 길이/구간: `BOUNDS`, `DUR`. **`DUR`를 바꾸면 `BOUNDS` 마지막 값과 최종 페이드 시작(`43.4`)도 같이 맞춘다.**
4. **렌더링한다.** 출력은 사용자가 열 수 있는 작업 폴더(예: `video/`)에 둔다.
   ```bash
   cd /tmp && python3 -I <스크립트경로>/make_video.py <출력>.mp4 <scratchpad>/bgm.wav [사진.jpg]
   ```
   45초 렌더링은 약 75초 걸린다. 임시 wav와 점검용 png는 scratchpad에 둔다.
5. **반드시 검증한다** (아래 체크리스트). 문제를 고치면 다시 렌더링하고 다시 확인한다.
6. 사용자가 요청하면 커밋·푸시한다. PR은 요청 시에만 만든다.

## 검증 체크리스트

- 길이/스트림: `ffprobe -v error -show_entries format=duration:stream=codec_type,width,height -of default=nw=1 파일.mp4` → 목표 길이, video+audio 모두 있어야 함
- 소리 크기: `ffmpeg -i 파일.mp4 -af volumedetect -vn -f null -` → 평균 약 -19dB, 최대 -6~-7dB 정도면 배경 음악으로 무난
- 장면별 프레임을 뽑아 contact sheet로 직접 본다(`ffmpeg -ss <초> -i … -frames:v 1`, 장면마다 1~2장 + 전환 구간). 볼 것:
  - 글자가 캐릭터·사진과 겹치지 않는지, 글자가 잘리지 않는지
  - 제목이 실제로 페이드인되는지(0.4~2초 프레임이 반투명인지)
  - Z·하트 같은 떠다니는 요소가 얼굴이나 제목을 가리지 않는지
- 전체를 끝까지 재생해 소리를 들어볼 수는 없다. 그렇다고 보고하지 말고 "프레임 단위로 확인"이라고 정확히 말한다.

## 환경 메모 (이 컨테이너 기준)

- 필요한 것: `ffmpeg`, Python `Pillow`, `numpy` (모두 설치돼 있었음).
- **한글 폰트는 WenQuanYi Zen Hei만 있다:** `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`. 다른 폰트로 바꾸면 한글이 깨질 수 있으니 바꾸기 전에 렌더링해서 확인한다. Z 글자는 DejaVu Sans Bold 사용.
- 파이썬은 `python3 -I`로 실행한다(현재 폴더의 파일을 import 하지 않도록).
- 설치형 플러그인(`hyperframes`, `onetake` 등)은 세션이 끝나면 사라지고, 새 세션에서야 로드될 수 있다. 이 스킬은 그런 것 없이 동작한다.

## 사진을 쓸 때

- 세 번째 인자로 사진을 주면 스토리 장면이 들어간다. 사진은 위쪽 기준으로 확대되고 서서히 줌인된다.
- **AI 생성 이미지의 표시(워터마크)는 지우지 않는다.** 화면 구도(위쪽 기준 확대)로 모서리가 잘려 나가는 정도만 쓴다.
- AI 생성 이미지는 상업용 홍보에 쓰기 전에 사용 조건을 확인하도록 사용자에게 알린다.
- 실제 제품 사진이 생기면 `make_char()` 그림 캐릭터를 사진 컷아웃으로 바꾸는 쪽이 가장 정확하다. 사진이 제품이 아닌 다른 이미지(예: 맹수 티라노)면 제품 이미지와 어긋나므로 사용 방식(배경만 / 오프닝만)을 사용자에게 먼저 묻는다.

## 알려진 한계

- 캐릭터는 코드로 그린 일러스트다. 눈 감기·눌림 등 동작은 이 그림 기준이며, 실제 인형 사진은 위치 이동·확대로만 움직인다.
- 음악은 합성음이라 전문 작곡 음원보다 단순하다. 음원 파일이 있으면 wav를 만드는 구간을 건너뛰고 `-i` 오디오로 교체한다.
- 장면 전환은 크로스페이드뿐이라 전환 순간에 두 장면의 캐릭터가 잠깐 겹쳐 보인다.
