# 병원 재고관리 템플릿 스킬

실제 병원에서 쓰는 재고관리 앱을 **판매·배포 가능한 템플릿**으로 바꾼다.
핵심은 두 가지다. 병원을 특정할 수 있는 정보를 빠짐없이 지우는 것, 그리고 지운 뒤에도 앱이 정상 동작하는지 확인하는 것이다.
특히 운영 중인 Apps Script 주소가 남으면 판매 후 구매자들이 실제 병원의 시트에 쓰기를 하게 되므로, 변환 후 잔존 검사를 통과하지 못하면 결과물을 내놓지 않는다.

## 구조

```
구글 시트(품목 / 실사기록 / 청구기록)
  ↕ Apps Script 웹앱 (Code.gs: doGet/doPost)
  ↕ fetch
index.html (스마트폰용 단일 파일 앱, SCRIPT_URL로 연결)
```

화면은 단일 HTML 파일이고 데이터는 전부 구글 시트에 있다. 서버·월 비용이 없다는 점이 판매 포인트다.

## 작업 순서

### 1. 원본 찾기
저장소에서 재고관리 HTML을 찾는다(예: `천안본_재고관리.html`). 원본은 절대 수정하지 않는다. 판매용은 항상 `product/inventory-template/` 같은 별도 폴더에 만든다.

### 2. 변환 (스크립트 사용)
```bash
python3 <skill>/scripts/sanitize.py --src <원본.html> --out product/inventory-template \
  --name "병원 정식명칭" --name "줄임말"
```
스크립트가 하는 일:
- `<title>`을 중립 제목으로 교체
- `--name`으로 준 병원명을 `(병원명)`으로 교체(여러 번 지정 가능, 띄어쓰기 있는 표기도 따로 지정)
- base64로 박힌 로고 이미지를 중립 SVG 아이콘으로 교체
- `SCRIPT_URL`을 `SCRIPT_URL_HERE`로 교체
- `assets/`의 `Code.gs`, `설치안내.md`를 출력 폴더에 복사
- 마지막에 잔존 검사: 병원명, base64, `script.google.com/macros` 주소, 전화번호, 이메일이 남아 있으면 **실패 코드로 종료**

`--name`에 넣지 않은 표기(약칭, 영문명)는 검사에 걸리지 않는다. 원본에서 `grep`으로 병원을 암시하는 단어를 먼저 훑어서 빠짐없이 지정한다.

### 3. 검증 (매번, 변환 직후)
변환 스크립트(2단계)가 화면 JS 문법과 잔존 검사를 이미 수행한다. 여기서는 나머지 두 가지를 돌리고, 하나라도 실패하면 원인을 고쳐 2단계부터 다시 한다. 둘 다 실패 시 0이 아닌 종료 코드를 낸다.

```bash
# (a) 백엔드: 구글 서비스를 흉내 낸 모의 환경에서 API 전 구간 시험 (10개 시나리오)
node <skill>/scripts/test_backend.js product/inventory-template/Code.gs
# (b) 화면: 샘플 데이터로 모바일 크기 브라우저에서 열어 렌더링·콘솔 오류·병원명 잔존 확인
#     마지막 인자들은 남아 있으면 안 되는 병원명 표기
node <skill>/scripts/test_ui.js product/inventory-template/index.html <스크린샷.png> 병원명1 병원명2
```
스크린샷은 눈으로도 열어 본다. 레이아웃 깨짐은 스크립트가 못 잡는다.

### 4. 한계를 숨기지 않기
모의 환경 테스트는 실제 구글 환경과 다르다. 사용자에게 **실제 빈 구글 시트에 설치해서 `references/test-checklist.md`의 점검표를 돌려 보라**고 반드시 안내한다. 이 확인 전에는 "판매 준비 완료"라고 말하지 않는다.

## 앱 규약 (수정할 때 지켜야 할 것)
- API 형식은 `references/api-contract.md`를 따른다. 화면과 `Code.gs`가 이 계약으로 묶여 있어서 한쪽만 바꾸면 깨진다.
- 부서 목록은 `index.html`의 `const DEPTS`, 분류 순서는 `CAT_ORDER`에 있다. 새 병원에 맞출 때는 이 두 줄만 바꾼다.
- 환자 개인정보는 이 시스템에 넣지 않는다. 소모품·재고 관리용이다.
- 샘플 데이터는 반드시 가상의 품목만 쓴다.

## 판매 전 안내할 것
- 원본 저장소에 실제 Apps Script 주소가 커밋되어 있다면, 저장소가 공개일 때 노출된 상태다. 새로 배포해 주소를 바꾸라고 권한다.
- 판매용 폴더만 별도 저장소로 분리하는 것이 안전하다.
- 병원 취업규칙의 겸업 조항을 확인하게 한다.
